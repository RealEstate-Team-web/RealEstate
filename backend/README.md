# Real Estate Backend

Node.js + Express.js + MySQL backend API for the Real Estate Website.

## Prerequisites

- Node.js (v18 or later)
- MySQL (8.x or compatible)
- npm

## Installation

```bash
npm install
```

## Environment

```bash
cp .env.example .env
```

Open `.env` and configure your own local MySQL credentials:

| Variable | Example | Description |
|---|---|---|
| `PORT` | `5000` | Server port |
| `NODE_ENV` | `development` | `development` / `production` |
| `DB_HOST` | `localhost` | MySQL host |
| `DB_PORT` | `3306` | MySQL port |
| `DB_NAME` | `real_estate` | MySQL database name (create it first) |
| `DB_USER` | `root` | MySQL user |
| `DB_PASSWORD` | `your_password` | MySQL password |
| `CLIENT_URL` | `http://localhost:5173` | Allowed CORS origin |
| `JWT_SECRET` | `change_me` | Secret used by the Authentication module |
| `JWT_EXPIRES_IN` | `7d` | JWT access token expiry |
| `CLOUDINARY_CLOUD_NAME` | `your_cloud_name` | Cloudinary cloud name |
| `CLOUDINARY_API_KEY` | `123456789` | Cloudinary API key |
| `CLOUDINARY_API_SECRET` | `your_secret` | Cloudinary API secret (never commit) |
| `CLOUDINARY_FOLDER` | `real-estate` | Base folder in Cloudinary for uploads |

Create the database if it does not exist:

```sql
CREATE DATABASE IF NOT EXISTS real_estate;
```

## Run development server

```bash
npm run dev
```

Starts the server with nodemon and auto-reloads on changes.

## Production-style run

```bash
npm start
```

## Database & migrations

All database schema changes are version-controlled migration files in `backend/database/migrations/`.

- Apply migrations: `npm run migrate`
- Create a new migration: `npm run migrate:create -- <name>`
- Read the migration rules before creating tables: [`backend/database/migration-tables.md`](database/migration-tables.md)

The shared MySQL connection pool lives in `backend/config/db.config.js` and reads credentials from `.env`.

## Image uploads (Cloudinary)

User-uploaded images (property gallery, agent/buyer profile images) are stored in Cloudinary. The database only stores `image_url` and `public_id`.

**Folder structure (fixed convention):**

```
real-estate/
├── properties/{propertyId}
├── agents/{agentId}
└── profiles/{userId}
```

The folder path is generated by `buildFolder(scope, entityId)` in `services/upload.service.js` and is never taken from client input.

- **Each developer uses their own Cloudinary account.** Create a free account at cloudinary.com and put your own credentials in your local `backend/.env` (`CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`). Production uses a separate dedicated account configured in the deployment environment.
- Config module: `backend/config/cloudinary.config.js`
- Upload service (shared): `backend/services/upload.service.js` — `uploadImage(buffer, { scope, entityId, publicId })` → `{ secureUrl, publicId }`, `deleteImage(publicId)`, `buildFolder(scope, entityId)`. Valid `scope` values: `properties`, `agents`, `profiles`. Invalid scope or `entityId` throws `UploadValidationError` (400).
- Authorization (shared): `backend/services/upload.access.js` — `assertUploadAccess({ scope, entityId, user })` verifies the authenticated user may upload to the entity: own profile only (`profiles`), own agent image only (`agents`), or the property owner/admin (`properties`, requires the `properties` table from Dev 2's migration). Throws `UploadAccessError` (403).
- Multer middleware: `backend/middlewares/upload.middleware.js` — memory storage, JPG/PNG/WebP only, 5 MB per file
- Verify your credentials: `npm run upload:check` (pings Cloudinary, uploads and deletes a test image)
- **Feature endpoints own the upload workflows.** There is no generic upload endpoint. Example (owned by the property feature, Dev 2):

```js
await assertUploadAccess({ scope: "properties", entityId: propertyId, user: req.user });
const { secureUrl, publicId } = await uploadImage(req.file.buffer, {
  scope: "properties",
  entityId: propertyId,
});
// then insert image_url + public_id into property_images
```

`upload.service.js` and `upload.access.js` are shared — communicate changes to them like a shared table.
